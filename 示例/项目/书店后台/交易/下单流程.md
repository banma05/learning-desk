> 状态: 学习中
> 更新: 2026-01-07

一本书从被下单到送到读者手里的主干。2026-01-05 和 Claude 一起读 `order-service` 时讲的，依据是代码（当时没记行号）。

## 打个比方：在餐馆点菜

| 在餐馆 | 在书店后台 |
|---|---|
| 你点单 | 创建订单，状态"待支付" |
| 后厨先把菜留出来 | 预占库存 |
| 你付钱 | 跳到支付平台付款 |
| 支付平台通知餐馆"钱到了" | 支付回调 |
| 上菜 | 发货 |

## 主干：下单五步

1. **下单**：`OrderController.create` 生成订单号，订单状态是"待支付"。
2. **预占库存**：先把书留出来，不是真扣；30 分钟没付钱就还回去。见[库存扣减](库存扣减.md)。
3. **付钱**：读者跳到支付平台付款。
4. **支付回调**：支付平台调我们的 `/pay/callback`，订单改成"已支付"，预占变成真扣。见[支付回调](支付回调.md)。
5. **发货**：见[发货](../履约/发货.md)（只看了一半）。

## 订单状态怎么变

- 下单后："待支付"。
- 支付回调后："已支付"。

## 订单号生成

订单号在 `OrderController.create` 里生成。怎么生成（格式、怎么保证不重复）这次没看。

## 用到的套路

- [先受理后回调](../../../概念/先受理后回调.md)：第 3、4 步，读者去支付平台付钱，钱到没到由支付平台事后调回调通知我们。
- 补偿任务：第 2 步，定时任务 `ReleaseStockJob` 把超时没付钱的预占还回去。
