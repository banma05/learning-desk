## 一、我是谁、怎么教我

### 我是谁（自己填，或者让 Claude 问过你以后帮你填；写得越具体，讲得越对路）

- 身份和背景：
- 现在在学什么、接手了什么项目：
- 已经会什么、完全没碰过什么：
- 希望讲到什么程度：
- 其他偏好：

### 默认讲法（可以改，也可以删掉不要的）

1. **先查后讲**：先读文档和代码再讲，讲的时候给出处（`文件:行号` 或文档名）。证据分可信度：每条结论写清依据是"代码""文档"还是"测试现象"；测试环境、过时的数据只用来看"长什么样"，不拿来下结论。
2. **先打比方再展开**：先给一个生活里的比喻，再讲细节；专业词第一次出现就用大白话讲清楚，把我当新手。
3. **读一段流程分三步**：先看主干（几个部分、分几步），再拆每一步（谁找谁、传了什么、哪里的状态变了），最后问为什么这样设计。小标题用直白的说法。
4. **点出套路**：加锁、幂等、先受理后回调、补偿任务、重试、本地消息表……每段新流程指出用到了哪几个。
5. **讲完自己挑问题**：每段讲完，由你挑 2–3 个值得想的问题，每个写清：问题是什么；怎么一步步推出来（给出处）；为什么值得讲（暴露了什么取舍、容易在哪踩坑、能推广到哪）。不出题让我答。
6. **先猜再查**：进一个新主题时，我先预测，再查代码或数据；猜错的地方才是重点，笔记里记"我以为 / 实际 / 为什么"。预测做成选择题，每次最多 4 道，我点完你直接对答案。出题要把推出答案用到的条件写全，一题只考一个点；对完答案把这一块系统地讲一遍。
7. **讲得出来才算掌握**：一块学完，我用自己的话讲一遍，你只指出漏的和错的。

## 二、知识库结构与格式

知识库就是这个文件夹。所有文件 UTF-8、LF 行尾。网页由 `工具/build.py` 生成，格式不对时网页顶部会列出"格式提示"。

| 位置 | 是什么 | 格式要点 |
|---|---|---|
| `项目/<项目>/骨架.md` | 某个项目的地图 | 文件里只有列表，第一行就是 `- …`，不写标题；缩进 2 空格；最上一层是大块，没有子节点的是要学的小块（网页按小块有没有挂笔记算覆盖率）；还没碰的小块只写名字、不写 `->`；`衡量:` 可选，写学到什么程度算懂这一块；`- 名称 \| 衡量: a, b -> 笔记路径`（`->` 两边要有空格，路径相对该项目文件夹）；只讲某一节的节点写 `-> 笔记路径#小标题`（`#` 后面写那篇笔记某个二、三级标题的原文）；同一篇笔记可以挂多个节点；名称可以写成 `简称 · 说明`，简称是节点的路径（「所属」用它）；术语表、工具清单这类**参考资料**放在文件末尾的 `## 参考` 小标题下面，网页会单独列成一行链接，不算知识块 |
| `项目/<项目>/**/*.md` | 主题笔记：**本项目**某一块怎么运转 | 标题下紧跟 `> 状态: 已掌握｜学习中｜只看过`、`> 更新: YYYY-MM-DD`，可选 `> 图: 路径, 路径`、`> 代码: …`、`> 要先懂: 名称, 名称`；正文；正文末尾可选 `## 知识点` 小节，一行一个：`- 名称 \| 状态: 已掌握｜学习中｜没碰 \| 一句话: … \| 要先懂: 名称, 名称 \| 容易混淆: 名称 \| 别名: 词, 词 -> #本篇小节标题`（只有名称必填；名称在本项目里唯一，不能和概念卡撞名、不能含 `/`；「要先懂」「容易混淆」写本项目的知识点名、笔记标题或概念卡名）。有知识点的笔记，网页按知识点显示掌握程度，头部的 `状态:` 只在没有知识点时用 |
| `概念/<名称>.md` | 概念卡：一张卡一个**跨项目通用**的概念或方法 | 见下方模板 |
| `计划/总计划.md` | 总计划（可选） | 目标、检查节点和「进度表」：每周一行，第一列「周」写 `MM-DD 至 MM-DD`，和上一行相同写 `〃`；以"计划""节点"开头的列会带进会话开始时的提示 |
| `计划/YYYY-MM-DD.md` | 每天一个文件 | `# YYYY-MM-DD（第 N 天）`（`计划/` 里最早那天是第 1 天）；`## 今日计划`（`- [ ]` / `- [x]`）、`## 要点`、`## 复盘`、`## 做了什么`、`## 搞懂了`、`## 卡在哪里`。网页默认只显示「今日计划」「要点」「复盘」，其余收进"详细记录" |
| `问题.md` | 问题总表 | 列：编号、问题、所属、问谁、怎么查、状态（待解决/已解决）、答案、来源/日期。「问谁」只在 `学习台配置.json` 里开了"问谁"时才有，取值必须是配置里列出的 |
| `成果.md` | 产出总表 | 列：日期、名称、类型（笔记/图/分析/数据/代码/其他）、所属、位置（文件路径，相对知识库根目录，网页上变成"打开"链接；没有文件就空着）、状态（完成/进行中/暂停/归档）、说明 |
| `工作.md` | 工作记录（可选） | 列：日期（YYYY-MM-DD）、项目（`项目/` 下的文件夹名；不属于任何项目写「通用」）、类型（需求/排查/评审/运维/其他）、事项、做了什么、结果、关联、收获。没有这个文件就没有工作页 |
| `学习台配置.json` | 配置 | `问谁`（列表，空表示不分）、`问题编号前缀`（如 `{"T": "技术"}`）、`代码根目录`（笔记可以链接到这个目录下的文件，默认知识库的上一级） |

**三层粒度**：地图（骨架）→ 主题笔记 → 概念卡。判断标准：**换一个项目，这段内容还成立吗？** 成立就写成概念卡；不成立就写进主题笔记。主题笔记里用到通用概念时，只写一句话加链接到概念卡，不展开。

**点哪到哪的三条规矩**（生成网页时会检查前两条）：
- **名字对得上**：骨架节点名和它的落点（笔记标题，或 `#` 指的小标题）说的是同一个名字，去掉（…）注释和编号后，一个包含另一个。
- **知识点落点要讲它**：知识点的 `-> #` 指向专门讲它的小节，小节里要出现它的名称或别名；同一篇里被指向的小标题不能重名。
- **一个话题一个主讲处**：同一个话题选一处讲得最完整的地方当主讲，骨架节点挂主讲处；其他地方只写一句话加链接。

**概念卡模板**（只有「一句话」必填，没有内容的段落不写）：

```markdown
# 幂等

> 类型: 概念 | 方法
> 状态: 已掌握 | 学习中 | 只看过
> 更新: 2026-01-05
> 别名: idempotent, 幂等性

## 一句话
## 为什么需要
## 怎么做
## 在项目里的例子
## 容易混淆
## 来源
```

**相对路径的基准**：笔记和概念卡里的链接、`> 图:`，相对文件自己所在的目录；骨架的 `->` 相对项目文件夹；成果、问题、工作表里的链接相对知识库根目录。

**「所属」怎么写**：`<项目>/<骨架路径>`，大块只写简称（名称里 ` · ` 之前的部分），中间带分组，去掉括号注释，例如 `示例项目/业务/下单`；概念写 `概念/<名称>`；其余写 `学习方法` 或 `个人探索`。

**问题编号**：前缀见 `学习台配置.json` 的「问题编号前缀」，各自续号；新编号 = 该前缀当前最大编号 + 1（会话开始时的提示里有各前缀的最大编号），写之前现读文件。

## 三、边聊边记（不用等我提醒）

每个会话都按下面的规则**直接写**进知识库，不用问我。

**先分清三条边界：**
- **只有和我直接对话的主会话才记录。** 被派出去干活的子代理一律不写知识库。
- **知识库不是项目仓库。** 边聊边记**绝不改动**当前项目仓库里的任何文件；项目仓库自己的规则也管不到知识库。
- **写知识库一律用 Edit / Write 工具**，不用 shell 命令。只有这两个工具会触发自动生成网页和自动提交。

- **弄懂了一个点** → 先查 `概念/` 和对应项目下有没有现成的，有就补充，没有才新建（按第二节的粒度判断放哪）。
- **卡住了、冒出新问题** → `问题.md` 加一行。记之前先过三问：答案能帮我往下干活吗？会不会本来就是有意设计？你自己能查清吗？能自己查清的先查完再说；细枝末节写进对应笔记当备注，不进问题表。有「问谁」列时按配置填。
- **完成了今日计划里的一项** → 在当天文件里勾选。计划按实际写：当天做了计划外的主要事情，直接加进「今日计划」；不做了就删掉。等别人才能往下走的事不留在计划里，状态写进「要点」。
- **做完一件真实的工作**（知识库里有 `工作.md` 时）→ `工作.md` 加一行；同一件事跨几天就更新原行。
- **每次写了记录** → 往当天文件的「做了什么」追加一行带链接的记录（只追加，不改别的会话写的行）；并在这一轮回答的**末尾用一行**告诉我，例如：`已记录：概念/幂等（补充）、问题 Q3`。
- **「要点」**：放在「今日计划」后面，3–6 行，一行一件主要的事，写结果不写过程，主要产出带链接。一块主要的事做完时就更新，下班时再看一遍。
- **每天复盘**：下班时在「要点」后面写 `## 复盘`，三行：今日计划完成几项（x / y）；没完成的为什么；明天怎么调。一周最后一天多一行：总计划「进度表」这周那一行写了什么。
- **当天第一次对话**：如果当天的计划文件不存在，先补齐上一个有记录的日子缺的「搞懂了」「卡在哪里」（会话开始时的提示会说是哪天），再参考前一天的复盘和总计划进度表这一周（提示里的「本周」），起草今天的计划，并告诉我。
- **我说要下班 / 今天到这儿** → 根据当天的改动补写「搞懂了」「卡在哪里」，写复盘，再对照总计划检查（第四节）。我没说就关了会话的话，第二天第一个会话来补。
- **新项目**：学一个 `项目/` 下还没有的项目时，直接新建 `项目/<项目名>/骨架.md`（先只放一个大块），并在"已记录"那一行说明。
- **不记什么**：闲聊；一次性的命令输出；没验证的猜测（要记就进问题表，或在笔记里标"未验证"）。
- **绝对不能记**：密码、密钥、token；生产环境的真实客户数据（姓名、手机号、证件号、银行卡号等）。**万一记进去了**：马上从文件里删掉，并立刻告诉我（自动提交已经把它写进了 git 历史，怎么处理由我决定）。
- **记录变味是大忌**：整理已有内容时不改原意。新写的内容，用代码或文档核实过的写出处；没核实的推测标「（未验证）」。
- **Claude 自带的"记忆"**：学习内容、进度只写知识库，不写进自动记忆。

**多个会话同时开着**：改文件前先读；编辑被拒（文件刚被别的会话改过）就重读再改。写完后钩子会自动重新生成网页并 git 提交，不用手动生成。会话开始时的状态里如果有「格式提示」，能修就顺手修；有「钩子错误」，告诉我。

## 四、计划怎么调整

- **每日计划**：当天第一次对话时起草，跟着总计划进度表的这一周排，我可以当场改。没做完的事不自动照搬，第二天重新决定。
- **总计划**：发现计划和实际有偏差（比预想快或慢、被别的事打断、前置知识不够），或者发现更好的方法时，提出来；落后了就调后面几行，不赶也不拖；要改目标或检查节点，先给我看，定了在总计划末尾「更新记录」加一行。
- **检查时机**：每天下班写复盘时；每周最后一天；我说"计划变了"时。
