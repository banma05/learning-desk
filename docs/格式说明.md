# 格式说明

规则以知识库里 `维护约定.md` 的第二节为准，Claude 每个会话都读它。这里给每种文件配一个[示例知识库](../示例/)里的真实文件，方便对照。格式不对时，网页顶部会列出"格式提示"，交给 Claude 修就行。

## 项目地图：`项目/<项目>/骨架.md`

示例：[示例/项目/书店后台/骨架.md](../示例/项目/书店后台/骨架.md)

```markdown
- 交易
  - 下单 | 衡量: 讲清下单五步, 讲清订单状态怎么变 -> 交易/下单流程.md
  - 支付 · 支付与支付回调 | 衡量: 讲清回调做的事, 讲清幂等和验签 -> 交易/支付回调.md
- 履约
  - 发货 | 衡量: 讲清物流单号怎么回填 -> 履约/发货.md
  - 退货
```

- 文件里只有列表，第一行就是 `- …`，缩进 2 空格。
- 最上一层是大块，也就是项目页上的一张张卡片；没有子节点的是小块。覆盖率 = 挂了笔记的小块 / 全部小块。
- `名称 | 衡量: a, b -> 笔记路径`：`衡量` 可选，写学到什么程度算懂；路径相对项目文件夹；还没碰的小块只写名字，比如上面的"退货"。
- `简称 · 说明`：简称是这个节点在「所属」里的写法，说明是给人看的全名。
- 术语表这类参考资料放在文件末尾的 `## 参考` 下面。

## 主题笔记：`项目/<项目>/**/*.md`

示例：[示例/项目/书店后台/交易/支付回调.md](../示例/项目/书店后台/交易/支付回调.md)

```markdown
# 支付回调

> 状态: 学习中
> 更新: 2026-01-06
> 要先懂: 下单流程, 先受理后回调

（正文，二、三级小标题分节）

## 知识点

- 回调幂等 | 状态: 学习中 | 一句话: 支付平台重复通知时，同一个支付单号只生效一次 | 要先懂: 幂等 -> #回调幂等
```

- 标题下面紧跟头部：`状态`、`更新` 必写，`图`、`代码`、`要先懂` 可选。
- 末尾的 `## 知识点` 可选，一行一个，字段之间用 ` | ` 隔开，只有名称必填；`-> #小标题` 指向专门讲它的那一节，那一节里要出现它的名称或别名。
- 有知识点的笔记，网页按知识点显示掌握程度，知识图谱也由知识点组成。

## 概念卡：`概念/<名称>.md`

示例：[示例/概念/幂等.md](../示例/概念/幂等.md)

一张卡一个**换个项目也成立**的概念或方法。头部写 `类型`（概念 / 方法）、`状态`、`更新`，可选 `别名`；正文只有「一句话」必写，其余（为什么需要、怎么做、在项目里的例子、容易混淆、来源）有内容才写。

## 每日计划：`计划/YYYY-MM-DD.md`

示例：[示例/计划/2026-01-06.md](../示例/计划/2026-01-06.md)

标题是 `# YYYY-MM-DD（第 N 天）`，下面是「今日计划」（`- [ ]` / `- [x]`）、「要点」、「复盘」、「做了什么」、「搞懂了」、「卡在哪里」。网页默认只展开前三节。

## 总计划：`计划/总计划.md`（可选）

示例：[示例/计划/总计划.md](../示例/计划/总计划.md)

目标、检查节点，再加一张「进度表」：每周一行，第一列「周」写 `MM-DD 至 MM-DD`，和上一行相同写 `〃`。以"计划""节点"开头的列，会在会话开始时带给 Claude。

## 三张表：`问题.md`、`成果.md`、`工作.md`

示例：[问题](../示例/问题.md)、[成果](../示例/成果.md)、[工作](../示例/工作.md)

都是一段说明加一张 Markdown 表格，列名和顺序见维护约定第二节。

- `问题.md`：只有在 `学习台配置.json` 里开了"问谁"时才有「问谁」这一列，取值必须是配置里列出的。编号前缀也看配置，比如 `T1`、`Q1`。
- `成果.md`：「位置」写文件路径（相对知识库根目录），网页上会变成"打开"链接；没有文件就空着。
- `工作.md`：可选，没有这个文件就没有工作页。

## 设置：`学习台配置.json`

```json
{
  "问谁": ["自己", "同事", "上级"],
  "问题编号前缀": {"T": "技术", "B": "业务", "Q": "思考", "L": "学习方法"},
  "代码根目录": ".."
}
```

- `问谁`：写成 `[]` 就不分。
- `问题编号前缀`：键是一个大写字母。
- `代码根目录`：笔记可以链接到这个目录下的文件，相对知识库根目录。

哪一项写错了，就按默认值处理，网页上会多一条格式提示。
